# Day 4：真实科研数据接入与理解

## 1. Synthetic 与真实数据有什么不同

Day 3 用人为设定的 tanh 曲线训练完整工作流。它容易检查，因为列名、采样、零点都已知；但不能证明程序读得懂真实模拟输出，更不能证明 MuMax3 与 COMSOL 谁更准。

Day 4 读取已有模拟结果，不重新运行软件。真实文件可能带 BOM、科学计数法、不同列名或分隔符，时间网格也可能不同；必须先检查当前文件而不是强行套用 synthetic 的格式。

## 2. 为什么不能直接把真实数据塞进 GitHub

科研数据可能含未发表结果、用户目录、设备信息或他人资料。Git 有历史，删掉文件不等于删掉历史，因此应从一开始隔离；公开仓库只存逻辑与合成测试，真实数据留在原位置只读。

`.gitignore` 只影响未跟踪文件，不是加密或访问控制。已跟踪的敏感文件仍可能被提交，提交前还要检查暂存区；本次没有把真实 CSV 或科研 PNG 加入 Git。

## 3. Local config 是什么

`config/data_sources.local.json` 是只有本机拥有的数据地址簿。可以提交的 `config/data_sources.example.json` 只含占位路径，供他人配置；新机器没有 local config 时，列表为空，不自动寻找或读取私人文件。

配置可将 alias 映射到一个绝对 CSV 路径，也可以用 `datasets` 组合两个已注册成员。每个成员可指定 label、时间列、磁化列、时间单位；它表达明确授权，不是让模型任意浏览硬盘。

## 4. 为什么用 dataset alias

模型看到的是 `fem_fdm_j25` 这样的业务名称，而不是私人绝对路径。用户负责配置允许访问的文件，Python 根据 alias 查地址；未注册名字、任意路径、非 CSV 和路径偏移会被拒绝。

 alias 也不是完整隐私保护。内容、描述、文件名仍可能敏感；程序隐藏常见路径，但不是生产级脱敏系统。

## 5. Adapter 做什么

Adapter 是格式适配逻辑，不一定需要独立的类。本项目用 `micromagnetics.py` 中的函数将选定列映射到 `time/mz/source` 长表，让后面的比较、采样、摘要不必关心原软件列名。

单文件可含多条 mz 列，组合可含两个独立文件。适配不等于重采样：两份文件保留自己的时间点，只有计算 crossing 或查询目标时间时，才在局部区间插值。

## 6. 不同软件为什么 CSV 格式不同

导出设置、单位系统、采样策略和后处理方式不同，都会改变列名、编码与时间网格。本次原始文件都采用 `time_ps/avg_mz`，却不是相同时间点；汇总表虽然名字写 FEM/FDM，却只有统计结果，不是时间序列。

因此先判断“文件代表什么”，再计算。不能靠文件名认定格式，也不能拿汇总表重复报出数字就说复现了原始曲线分析。

## 7. Schema / 列结构是什么

DataFrame 是带列名与类型的二维表。数据 schema 可以包含时间列、磁化列、单位、行数及缺失值；tool schema 则描述工具参数，让模型知道应提供什么 JSON，它们不是同一个概念。

识别列名先精确匹配，再忽略大小写和部分标点做规范化匹配；实际列 `avg_mz` 已加入适配。若有多个时间候选或无法识别，就要求明确指定，不按数据大小偷偷猜列。

## 8. 单位为什么重要

数值 100 可能是 100 s、ns 或 ps，差数个数量级。列名 `time_ps`、`Time (s)` 等可给出单位，裸 `time` 只能返回 `unknown`。

已知单位通过比例换算统一。对于无单位数据，显式 `time_unit` 是用户声明原数据单位，不是程序发现的事实；组合未知单位时应先分别确认成员配置，不能因为曲线看着相近就假设 ps。

## 9. 如何复用 Day 3 的 switching time

共享函数在 `curve_analysis.py` 中检查数值有限性、按时间排序、拒绝重复时间，然后寻找首个负到正区间。

```text
t_switch = t1 + (0 - m1) × (t2 - t1) / (m2 - m1)
```

Day 3 仓库 CSV 与 Day 4 注册数据共用此计算，不复制两份算法。输出包含区间、方法、单位、来源和是否发生重排；起始为 0 没有此前负值时，不算已确认负到正 crossing。

取值工具默认 linear，也支持 nearest。目标恰好等于已有时间点时返回原始值；超出采样范围报错，不外推。摘要的 crossing_count 只统计负到正次数，不是所有正负振荡次数。

## 10. 为什么真实验证更有说服力

真实粗网格 J2.5E12 曲线复算得到 MuMax3 73.83834774284676 ps、COMSOL 72.81911124409665 ps；差 1.019236498750118 ps。100 ps 的 mz 为 0.9564934、0.962276697685，都是原始点；当前既有汇总表的四个值与复算完全一致。

这同时检验了编码、列名、单位、非共用采样网格与结果追溯。它只能证明当前文件/判据下的数值流程一致，不证明模型物理准确、不量化网格误差，也不证明自然语言永不出错。

## Day 4 我真正应该理解的 5 件事

1. LLM 选择工具，Python 执行工具；真实数值来自被授权的数据与算法。
2. 外部数据授权靠本地 registry；公开 example 与私人 local 文件分开。
3. 标准化只统一含义与单位，不应悄悄改变原生采样或猜列。
4. 首次过零定义、插值区间与最终磁化状态是不同概念。
5. 验证要同时检查测试、真实复现、解释、原文件只读与 Git 暂存区；生成了代码不等于自己已经理解代码。
