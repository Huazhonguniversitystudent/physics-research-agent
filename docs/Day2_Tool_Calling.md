# Day 2：Tool Calling 与最简单的 Agent Loop

## 1. 普通 LLM 和 Agent 有什么区别

普通 LLM 接收文字，再生成文字：

```text
用户问题 → LLM → 文字回答
```

Agent 在这个过程里增加了“行动”。模型可以判断是否需要工具，程序执行工具后再把结果交给模型：

```text
用户任务 → LLM 判断 → 工具调用 → Python 执行 → 工具结果 → LLM → 最终回答
```

因此，Agent 不是另一种模型，而是“模型 + 工具 + 控制循环”组成的程序。

## 2. 什么是 Tool Calling

Tool Calling 是模型用结构化数据表达工具请求的机制。比如模型不会直接运行计算器，而是返回类似信息：

```json
{
  "name": "calculator",
  "arguments": {"expression": "12345 * 6789"}
}
```

这表示模型认为应该调用 `calculator`，并建议把 `12345 * 6789` 作为参数。

## 3. tool schema 是什么

tool schema 是工具的“说明书”，主要告诉模型：

- 工具叫什么名字；
- 工具能做什么；
- 参数有哪些；
- 每个参数是什么类型；
- 哪些参数必须提供。

模型读取 schema 后，才能选择合适的工具并生成正确参数。schema 只描述能力，不会自动执行 Python。

## 4. 到底是谁执行 Python

模型没有进入本机，也没有直接调用函数。模型只输出：

1. 调哪个工具；
2. 传什么参数。

真正执行工具的是我们的 Python 程序。程序解析模型返回的工具名和 JSON 参数，调用本地函数，再把结果发送回模型。以计算器为例：

```text
用户
↓
LLM
↓
function/tool call
↓
Python
↓
calculator()
↓
结果
↓
LLM
↓
自然语言答案
```

## 5. Agent Loop 是什么

一次任务可能需要零次、一次或多次工具调用。Agent Loop 每一轮都检查模型输出：

- 如果模型给出最终文本，就结束并返回答案；
- 如果模型请求工具，就执行工具、回传结果，然后进入下一轮。

本项目把 `MAX_STEPS` 设为 5。限制步数可以防止模型反复调用工具造成无限循环、额外费用或长时间等待。超过限制时，程序会明确提示用户简化问题。

## 6. 为什么不能直接使用 eval()

`eval()` 会把字符串当成任意 Python 代码执行。如果把模型或用户生成的内容直接交给它，攻击者可能读取文件、导入模块或运行系统命令。

本项目使用 Python 的 `ast` 解析表达式，只允许明确列出的运算符、函数和常数。属性访问、导入、文件操作、系统命令和未知函数都会被拒绝。

## 7. 今天的数据流

以“一个电子经过 5 V 电势差后获得多少能量”为例：

1. Python 把用户问题和两个工具的 schema 发给 DeepSeek。
2. DeepSeek 返回 `electron_energy_from_voltage` 和参数 `voltage_v=5`。
3. Python 调用本地物理函数。
4. 函数返回 `5 eV` 和 `8.01088317e-19 J`。
5. Python 把这个结果作为 `function_call_output` 发回 DeepSeek。
6. DeepSeek 根据结果生成自然语言答案。

如果问题是“天为什么是蓝色的？”，模型可以不调用工具，直接解释瑞利散射。

## 我今天应该真正记住的 5 件事

1. Agent 是“模型 + 工具 + 控制循环”，不是一个神秘的新模型。
2. Tool Calling 中，模型只选择工具并生成参数，不会亲自执行 Python。
3. Python 程序负责执行工具，并把真实结果交回模型。
4. Agent Loop 让模型能够在结果返回后继续判断，`MAX_STEPS` 防止无限循环。
5. 永远不要对模型或用户输入直接使用 `eval()`；工具必须限制可执行能力。
